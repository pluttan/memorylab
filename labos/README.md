# labos

Компьютер загружает labos с флешки вместо операционной системы. labos проводит опыты лабораторной работы прямо на железе. Графики labos рисует на экране. Управлять им можно по сети командой `labctl.py`.

Операционная система мешает замерам. Она выделяет страницы при первом обращении, прерывает опыт ради других программ и скрывает физические адреса. Без неё опыты дают одни и те же числа от запуска к запуску, а опыт 1 видит настоящие банки DRAM.

## Что умеет

- Меню, как окно PCLAB: слева список опытов, справа описание, задание методички и таблица параметров.
- Методичка: описания опытов из тетради memorylab, с таблицами, кодом и формулами.
- Ролики manim к опытам 1–7: labos сам декодирует видео H.264.
- Идентификация процессора (задания 1 и 2): модель, кэш-память всех уровней, буферы TLB, объём памяти.
- Опыт 1 «Расслоение динамической памяти» по конфликтам строк: число банков, размер строки (страницы) и число страниц.
- Опыты 2–7 пока есть только в меню, в методичке и в роликах. Их проводят в тетради memorylab.
- Графики в стиле лабораторной работы: шрифт GOST Type BU, палитра Catppuccin.
- Управление по сети: те же действия, что с клавиатуры.

## Клавиши

| Где | Клавиша | Действие |
|---|---|---|
| список опытов | вверх, вниз или цифра | выбрать опыт |
| список опытов | Tab или вправо | перейти к параметрам |
| параметры | вверх, вниз | выбрать параметр |
| параметры | цифры, Backspace | ввести значение |
| параметры | влево, вправо | уменьшить или увеличить значение |
| параметры | Tab или Esc | вернуться к списку |
| меню, результат | Enter | запустить опыт |
| меню, результат | F1 | открыть методичку на разделе опыта |
| меню, результат, методичка | F2 | показать ролик к опыту |
| методичка | вверх, вниз, PgUp, PgDn, Home, End | листать |
| методичка | влево, вправо | предыдущий или следующий раздел |
| ролик | пробел | пауза |
| ролик | влево, вправо | назад или вперёд на 10 секунд |
| ролик | Home | ролик с начала |
| результат, методичка, ролик | Esc | вернуться назад |
| везде | F10 | перезагрузить компьютер |

Значения по умолчанию подходят компьютерам лаборатории Lenovo и Kraftway. Значение вне диапазона labos заменяет ближайшей границей.

## Сборка

Нужны clang и lld-link из Homebrew (`llvm@22`, `lld@22`) или из пакетов Linux. Для роликов нужен `ffmpeg`, для QEMU нужен `qemu`.

```sh
make build         # build/esp/EFI/BOOT/BOOTX64.EFI
make content       # методичка и ролики в build/esp/labos
make test          # тесты чистых модулей на этой машине
```

`make manual` собирает методичку из тетради `lab/memory_experiment.ipynb` и текстов `manual/`. Текст `manual/cpuinfo.md` заменяет ячейку тетради про идентификацию процессора. Текст `manual/<опыт>.md` идёт после описания опыта из тетради.

`make films` пережимает ролики из `lab/films` в профиль H.264 Baseline: другие профили декодер labos не понимает. Каждый ролик выходит в двух размерах, 720p и 1080p, всего около 80 МБ. labos берёт самый крупный ролик, который не больше экрана.

## Запуск в QEMU

```sh
make qemu-headless # QEMU без окна, журнал в build/serial.log
make ping          # ответ labos по сети
make remote-screen # снимок экрана в build/remote.png
make stop
```

QEMU не моделирует время DRAM, поэтому опыт 1 там конфликтов не видит. Чтобы проверить рисунок, соберите labos с моделью памяти: `make build SYNTHETIC=1`. Модель процессора задаёт `CPU`: `make qemu-headless CPU=Skylake-Client` показывает кэш, как у компьютеров лаборатории.

## Запуск на компьютере

1. Отформатируйте флешку в FAT32 и запишите на неё labos, методичку и ролики: `make usb VOLUME=/Volumes/LABOS`.
2. В настройках UEFI выключите Secure Boot.
3. Если нужно управление по сети, включите в настройках UEFI сетевой стек (Network Stack или PXE). Без него UEFI не даёт доступа к сетевой карте.
4. Загрузите компьютер с флешки.

В нижней строке экрана labos показывает свой адрес.

## Управление по сети

```sh
L="venv/bin/python3.12 tools/labctl.py --host АДРЕС"
$L ping                       # адрес, экран, частота TSC
$L menu                       # опыты и текущие параметры
$L --timeout 120 run rowconf 2 15 > rowconf.txt   # опыт 1: блок 2 МБ, 15 повторов
$L run cpuinfo                # идентификация процессора
$L manual sorting_algorithms  # методичка на разделе опыта 7
$L film exp3                  # ролик к опыту 3
$L player                     # кадр ролика, сколько кадров показано и пропущено
$L key down tab right enter   # нажать клавиши, как на клавиатуре
$L screen screen.png          # снимок экрана
$L log                        # журнал labos
$L reset                      # перезагрузка
```

`run` заменяет параметры опыта по порядку и возвращает выводы и данные. Если ответ не дошёл, `labctl.py` запрашивает его снова, и labos не запускает опыт второй раз.

## Сторонний код

`third_party/h264bsd` содержит декодер H.264 из проекта [h264bsd](https://github.com/oneam/h264bsd), каталог `src/` версии `42bcb5d`. Декодер пришёл из Android, его лицензия Apache 2.0. Обёртки декодера идут по лицензии MIT. Текст лицензий лежит в `LICENSE.md`. Каталог `third_party/libc` даёт декодеру `malloc`, `memcpy` и другие функции, которых в UEFI нет.
